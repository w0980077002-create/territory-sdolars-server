3. ROOT CAUSE OF ERROR 10097
The deployed G123 server already had Durable Object migration v5:
  v5 -> new_classes = ["RoomHub"]
That creates the existing RoomHub namespace with the legacy KV backend.

Later commits changed the SAME historical v5 migration to:
  v5 -> new_sqlite_classes = ["RoomHub"]
This is invalid. Cloudflare explicitly says storage type is immutable for an existing Durable Object and that changing an already-deployed KV class to SQLite with new_sqlite_classes fails. Cloudflare's current documentation also says migration entries are applied once and historical migrations must not be rewritten.

A separate attempt then introduced RoomHubV2/v6. That is not necessary for the immediate production repair and creates an avoidable namespace migration.

4. CLEAN DEPLOYMENT DECISION
For the currently deployed G123 production worker, the safest repair is:
- restore v5 exactly as originally deployed: new_classes = ["RoomHub"];
- restore binding ARENA_HUB -> RoomHub;
- restore exported class name RoomHub;
- remove the experimental v6 migration;
- deploy the code changes as a normal update to the EXISTING Worker/DOs, with no new Durable Object lifecycle migration.

This preserves the existing namespace and its data instead of trying to change its storage backend.

6. SERVER AUDIT

- existing TerritoryDB SQLite database.

- admin auth cookie with HttpOnly/Secure/SameSite=Strict.
- Telegram bot button uses inline `web_app`.

Important remaining risks:
- /api/progress still accepts client-supplied progression/economy fields. The source comment itself says these should eventually become authoritative game events.
- /api/state protects base economy/progression fields, but other snapshot fields are still client-controlled. If the snapshot is treated as authoritative gameplay state, players could manipulate inventory/consumables/arena/story/etc.
- /api/setup-telegram-webhook is public and changes the bot webhook; it should be admin-protected or otherwise restricted.
- /admin/db-health and some diagnostic endpoints intentionally expose database diagnostics; these should not remain public in production.
- CORS is `*`. This is not the cause of 10097, but it is broader than necessary. After Telegram auth wiring is stable, the API should use an explicit allowed origin.
- The repository has no package.json in the server main branch. Pinning Wrangler is recommended for deterministic builds.
