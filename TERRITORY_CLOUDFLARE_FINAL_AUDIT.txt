Territory Sdolars — Cloudflare final deployment package
Date: 2026-09-29

ROOT CAUSE
The failing deployment was still attempting to provision/use the legacy KV-backed
RoomHub class through the old migrations chain (v5 new_classes = ["RoomHub"]).
Cloudflare now requires new Durable Object namespaces to use SQLite on affected
accounts / Workers Free.

FINAL CONFIGURATION
- TerritoryDB remains SQLite-backed.
- ARENA_HUB is bound to the new RoomHubSQLite class.
- RoomHub is retained only as an existing legacy-kv namespace declaration so an
  already-provisioned old namespace is preserved and is NOT bound to the Worker.
- RoomHubSQLite is declared as a new SQLite-backed Durable Object.
- The old migrations array (v4/v5/v6) is removed because Cloudflare's current
  declarative exports flow replaces migrations. These flows must not be mixed.

VALIDATION PERFORMED
- worker.js: node --check PASS
- no new_classes migration remains
- ARENA_HUB binding points to RoomHubSQLite
- exports.TerritoryDB storage = sqlite
- exports.RoomHub storage = legacy-kv (preserves existing namespace)
- exports.RoomHubSQLite storage = sqlite
- package.json uses Wrangler 4.143.0

IMPORTANT
Cloudflare Workers Builds must build the current main branch commit. A retry of an
old build can reuse that old commit. Push a new commit to the configured production
branch, or verify the build page shows the new commit before deployment.
